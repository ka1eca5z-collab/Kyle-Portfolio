EG2A16 · CLOUD COMPUTING DEVELOPMENT

Cloud E-commerce Product Catalogue

A cost-aware AWS application that separates compute, relational data and object storage while applying security, reliability, performance, operations, cost and sustainability improvements.

AWS EC2RDS MySQLS3CloudWatchFlaskNginx
ConstraintUS$50 learner-lab budget
Application9-product catalogue
RegionAWS N. Virginia
ArchitectureEC2 · RDS · S3
01 / PROJECT SCOPE & PROBLEM

Build a reliable cloud application without losing control of cost or security.

The brief required a cost-effective, reliable, efficient and secure e-commerce application within a US$50 budget. The solution had to include a web server, VPC, database and object storage, with nine products displayed on the home page.

Product information needed to live in a database while product images were stored separately in object storage. This created a useful real-world architecture problem: connect multiple cloud services while keeping the application simple enough to operate inside a constrained learner environment.

CLOUD ARCHITECTURE

Separation of compute, data and object storage.

02 / MY ROLE & SOLUTION

I built the application and the cloud infrastructure it depended on.

I implemented the product catalogue on Amazon EC2 and connected the web layer to Amazon RDS and S3. Flask handled application routes and database access, while Nginx and Gunicorn served the application.

Application layer

Built the Flask product catalogue and Jinja template that renders database-backed product cards.

Data layer

Stored product names, prices and descriptions in Amazon RDS MySQL and connected Flask using PyMySQL.

Object storage

Stored the nine product images in Amazon S3 and separated static assets from the compute and relational database layers.

Cloud operations

Applied security-group hardening, S3 versioning and lifecycle rules, image optimisation and CloudWatch alarms.

03 / WORK PROCESS

Build the network first, then layer the application on top.

01

Network foundation

Created a VPC with public and private subnets across two availability zones and configured the project security group.

02

Compute & web stack

Deployed an Ubuntu EC2 instance and served the Flask application through Gunicorn behind Nginx.

03

Relational database

Created Amazon RDS MySQL for the products table, then connected the Flask application to retrieve product data dynamically.

04

Object storage

Uploaded product images to S3 and constructed matching object URLs from each product name in the web template.

05

Well-Architected improvements

Restricted MySQL exposure, enabled S3 Versioning, resized images, added CloudWatch high-CPU and idle-EC2 alarms, and configured lifecycle cleanup of noncurrent object versions.

FINAL APPLICATION

Database-backed catalogue, browser-ready.

The final website displayed all nine assigned kitchenware products with their images, names, prices and descriptions.

04 / OUTCOME & RESULTS

A functioning multi-service cloud application with deliberate operational improvements.

The final solution delivered the required nine-product e-commerce catalogue and demonstrated a complete request path from the Internet to EC2, Flask, RDS and S3.

✓Security

RDS MySQL access was restricted through the project security group rather than being open to all IPv4 addresses.

✓Reliability & performance

S3 Versioning protected overwritten images, while resized product images reduced transfer size and improved loading efficiency.

✓Operations & cost

CloudWatch alarms monitored high CPU and sustained idle usage, with the idle alarm configured to stop EC2 and reduce unnecessary runtime.

Operational trade-off

The complete website depends on both EC2 and RDS being running, so availability and cost need to be managed actively in the learner-lab environment. S3 object storage remains independent.
